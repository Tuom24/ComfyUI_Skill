# 任务匹配与组合规则

## 1. 任务分析

把用户的自然语言需求解析为三要素：目标产物（图像/视频）、已有素材、操作序列。

- 单项操作 → 单阶段计划；
- 多步操作 → 有序子任务序列，每个子任务只含一项原子操作，显式标注依赖：哪一步的哪个输出接到哪一步的哪个输入；
- 用户表述含糊时（如"把这张图弄得好看点"），先澄清要改什么、保留什么，再做匹配，不要猜。

## 2. 匹配：先类型过滤，再语义择优

对每个子任务，在卡片库中两轮筛选：

**第一轮 类型过滤（硬约束）**：候选的必填输入槽必须全部可满足——用户素材、上游产物或按 `desc` 默认行为的可选槽。类型不匹配直接淘汰，不做"差不多"的匹配。

**第二轮 语义择优（软排序）**：在类型兼容的候选中比较：

1. `task_family` 与子任务语义的一致程度；
2. `summary` 与子任务要求的贴合度；
3. `notes` 中的边界是否与本次输入条件冲突（如输入低分辨率图而 notes 标注低分辨率效果差）；
4. 用户在本会话早前反馈过的偏好。

每个子任务输出一个主候选 + 一个备选。备选用于优化轮换用。

**缺口处理**：无兼容候选时如实告知——列出最接近的候选与差距（缺什么输入槽、任务族不同），请用户补充素材、放宽要求或提供新工作流；不从缺口勉强拼凑。

## 3. 组合与产物传递

- 上游产物通过 `outputs_to` 映射写入下游输入槽，槽类型必须一致；
- 一个输出可以接到多个下游（分支复用），但一个输入槽只能有一个来源；
- 阶段依赖必须是单向的（后面阶段引用前面阶段），禁止循环；
- 参数优先取用户明确给出的值；用户未指定时取卡片 `default`，并把实际取值写进交付报告。

## 4. 多轮优化

执行交付后，用户反馈按三类处理，每轮只改与反馈相关的部分：

| 反馈类型 | 处理方式 |
|----------|----------|
| 需求理解偏差 | 回到任务分析，修正子任务序列后重新匹配 |
| 工作流选择不当 | 主候选与备选互换，或改选同 `task_family` 其他卡片 |
| 参数配置问题 | 只调整对应参数，工作流与阶段结构不变 |

每轮重新生成计划 → `validate_plan.py` 校验 → 执行 → 交付。用户认可的阶段保持不变（其产物可缓存复用）。同一问题连续两轮未解决时，停止重试，说明瓶颈并给出建议（补充素材/新工作流/人工在 ComfyUI 中调整）。

## 5. 交付报告

每轮交付包含：最终结果文件；各阶段使用的工作流 id 与名称；关键参数实际取值；若有未使用的备选或已知边界（notes 命中），一并说明。
